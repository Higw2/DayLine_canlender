# 实现规划

本项目按用户指定分工推进：Astra 规划、Terra high 实现、Sol medium 验收。

## 用户路径

1. 从 Ubuntu 应用列表启动，查看选定日期的时间线。
2. 创建事件，填写名称、开始和结束时间、备注；保存到本地 SQLite。
3. 关闭主窗口后保留桌面日程卡片和后台提醒。
4. 到点显示独立提醒窗口，可完成事件或延后提醒。
5. 从桌面卡片重新打开应用，或新建事件；显式退出停止应用。

## 技术选择

- Python 3 + GTK4/Libadwaita：使用 Ubuntu 24.04 的系统依赖，提供原生窗口、输入和桌面集成。
- SQLite：事件和提醒处理状态持久化，核心存储模块不依赖 GUI，可独立测试。
- 单实例 Gtk.Application：重新启动打开现有应用，避免多个进程重复提醒；持有应用生命周期，让提醒不依赖主窗口是否显示。
- 独立桌面窗口：仅在 X11 下申请桌面层级。编辑窗口保持普通窗口行为。
- 用户级安装：程序和数据分开存放，自启动可选，卸载保留日程。

## 视觉方向

中文优先，温暖浅灰、白色卡片与墨绿色强调色。主窗口通过日期选择、当天概览和纵向时间线组织内容。深色桌面卡片以清晰日期、当前时间和即将发生的事件为主，并保留新建与打开入口。无事件时展示可操作的空状态。

## 关键边界

- 提醒以“当前时间已达到计划时间且尚未提醒”为条件，不能依赖时间恰好相等。
- 状态保存在 SQLite，应用重启不应使已处理提醒再次出现。
- 仅修改标题或备注不应丢失延后提醒状态。
- 跨日事件在相应日期可见，重叠事件均应可操作。
- X11 桌面模式必须通过实际窗口属性及显示桌面行为验证；Wayland 普通窗口降级需明确告知。
- 电脑关机或挂起期间不能弹窗，不承诺闹钟唤醒硬件。

桌面窗口实现参考 [EWMH](https://specifications.freedesktop.org/wm/latest-single/) 与 [GdkX11.X11Surface.get_xid](https://docs.gtk.org/gdk4-x11/method.X11Surface.get_xid.html)。最终结果以 [验收记录](ACCEPTANCE.md) 为准。
